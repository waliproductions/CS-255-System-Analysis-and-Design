# CS 255 – System Analysis and Design

## DriverPass Project Reflection

### 1. Briefly summarize the DriverPass project. Who was the client? What type of system did they want you to design?

The client was DriverPass, a company that wanted to help students prepare for their driving tests. They needed an online system where customers could create accounts, select training packages, schedule driving lessons, take practice tests, and track their progress. The system also needed to help employees manage appointments, students, driving instructors, and vehicles.

### 2. What did you do particularly well?

I think I did particularly well creating the UML diagrams for the system. The diagrams helped me organize how customers, employees, and different parts of the system would work together. I paid particular attention to the scheduling process, including checking instructor and vehicle availability, preventing scheduling conflicts, and allowing customers to modify or cancel appointments.

### 3. If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

If I could revise one part of my work, I would improve the system design document by adding more detail about how the system should handle unexpected problems. For example, I would explain what happens if a customer's internet connection fails during scheduling or if an available appointment gets booked by someone else before the customer finishes. This would help the developers build a more reliable system.

### 4. How did you interpret the user's needs and implement them into your system design? Why is it so important to consider the user's needs when designing?

I reviewed the DriverPass requirements and identified the features customers and employees would need. I used those requirements to build diagrams showing how the system should function. For example, customers needed an easy way to schedule lessons, so I designed a process that checks availability, validates the reservation, and confirms the appointment. Considering the user's needs is important because the system should solve actual problems and be easy for people to use.

### 5. How do you approach designing software? What techniques or strategies would you use in the future to analyze and design a system?

My approach starts with understanding what the client needs before deciding how the system should work. I would gather requirements, identify the different users, and map out how the system should function. I would then use UML diagrams to organize the design before development begins. In future projects, I would also collect user feedback, review potential problems early, and test the design against the original requirements. This course helped me understand how important planning and communication are to successful software development.
